## 参加受付・実参加・面談

本人確認済みアカウントが自分で回答。申込と参加予定は既存の `yes` 回答を共通の状態として使用し、別の有料予約/契約を作りません。検討中/不参加も既存回答を使い、重複/定員競合/締切は既存トランザクションで防止します。締切後も専用の本人取消を可能にしました。旧respond APIの締切仕様は変更していません。

実参加/欠席は終了後、代表が根拠参照付きで確認した場合だけ、既存 `wf_attendance` のmanual/mock別記録へ保存。未回答や不参加を欠席と推測しません。面談希望は本人の明示入力または代表の観測根拠、完了は希望後の過去時刻と観測根拠が必要。面談希望で予約・契約・売上を作りません。

代表画面の申込一覧に氏名/アカウント/区分/回答を表示。関心は本人が選んだ健康・美容・働き方・つながり・その他だけで、診断/病歴などの詳細を入力させません。過去参加は同一事業・同一本人・同一実行区分の確認済み記録だけを参照。他事業の顧客を名前一致で統合しません。

## 案内・同意・承認・予定

個別案内と一斉案内は同じ検証を利用。一斉案内は最大200人ごとに個別下書きを作るだけで、まとめて承認・送信しません。未同意/不参加/権限外はスキップし、件数を監査します。既存キーを再確認した場合は同じ原稿IDを返し、新規作成件数と同一視しません。

すべて固定テンプレート・ルールで、LLM未使用/未送信と表示します。区分、本人申告の関心、同一事業での確認済み過去参加、日時、会場、内容、参加費を反映。健康効果・収入保証・法的性質の虚偽断定は機械的に検出し、人の確認も必要です。ベネシードの報酬/契約等は未確認情報を補完せず、公式規約の実査は未完了です。

| 原稿 | 必要条件・仮設定 |
| --- | --- |
| 個別/一斉案内 | 受付中/締切前、対象区分、全体同意＋新しいinvite同意 |
| 締切前 | reminders同意。代表設定の1〜168時間前、初期の仮設定24時間前 |
| 前日/当日 | 参加予定yes、reminders同意。JST時刻は仮設定09:00、代表が変更可能 |
| お礼/質問対応/面談提案 | 終了後の実参加確認＋followup同意。質問の具体的回答は代表確認待ちの案で、汎用回答AIは未実装 |
| 欠席後フォロー | 終了後の明示欠席確認＋followup同意。不参加/取消へは再勧誘しない |

既存の全体配信停止に加え、セミナーごとのinvite/reminders/followup目的別同意を本人が記録します。既存のモック用全体同意を新しい目的へ無断拡大しません。CRMへの明示関連がある場合は、その事業の連絡/日程/フォロー同意と停止も確認。モック案件でも既存の連絡停止を迂回できません。旧3日前ルートからも新しい目的別停止を確認します。

「下書き→代表承認待ち→承認済み送信待ち（API未接続）」で停止。修正は私的な旧版を保存し再承認へ戻します。承認には本文ハッシュ、セミナー/対象/本人登録/回答/同意/関心/実参加/顧客状態のスナップショットを用い、キュー取得時・模擬実行時も再検証。条件変更後の承認を再利用しません。モック成功済みの同種原稿を自動再送しません。

予定はDBに保存しますが、**常駐スケジューラーは未実装**。初期停止でWeb起動だけでは動かず、代表の有効化＋「本日分の下書きを確認・準備」で期限を確認します。自動送信はしません。仮設定として同日の候補は当日→前日→締切前の順に1種を準備。開始時刻より後の通知時刻は自動補正せず代表へ確認を要求します。過去日程の追いつき送信は行いません。既存3日前処理/IDは維持し、追加の3日前処理を作っていません。

模擬実行は承認・予定到来後のみ、最大3試行・60秒×試行回数のバックオフ。模擬結果不明は自動再試行せず照合待ち。原稿/版/対象の重複、同時実行、遅延操作を検証します。ネットワークを呼ばないため、実HTTPタイムアウト/結果照会/実LINE宛先管理は未実装です。

オンラインURLは秘密値なしのHTTPS参照のみ（クエリ/断片/埋込認証は拒否）。URLを取得・検証・外部予約へ送信しません。会議パスワードは入力せず、限定情報の安全な別送方法は将来設計します。

## 成果・財務の定義

- 集計範囲はそのセミナー全期間。申込者は一度でもyesで申し込んだ本人の集合で、取消後も母数に残します。
- 参加率＝実参加確認者/累計申込者、取消率＝現在noの既申込者/累計申込者、面談化率＝実参加者中の明示面談希望者/実参加者。母数0は未計測。確認していない実参加・面談完了を推測しません。
- 売上/費用は代表が根拠付きで明示配賦した同一事業の既存請求/実経費だけ。請求は同じ案件とセミナーが明示関連付け済みで、manual記録のみ。1つの根拠を複数セミナーへ重複配賦しません。誤配賦は代表が解除でき、元台帳と履歴は保持。
- 税抜請求売上−全額取消、確認済み入金−返金、確認済み経費を別掲。参加費×人数、見積、予測、モックは実売上にしません。銀行/取引先の実照合は未接続で、代表の確認申告であることを表示。
- 記録なしは未計測、明示記録した0は0。mockセミナーは実績を未計測とし、合成参考集計を別表示。実測と試算/モックを混同しません。

## DB・認証・事業分離・復旧

追加型SQLは `014_seminar_support.sql`。新規のs14_meta/consents/preferences/engagement/drafts/draft_history/attempts/work/attributions/scheduler/eventsで拡張し、既存セミナー/本人/回答/実参加/財務テーブルを参照します。既存行の自動変換、旧事業の改名、顧客の自動関連付け、既存データの削除はありません。

認証・Host/Origin・CSRF・nonce・CSP・エスケープ・要求制限は既存Webを継承。公開APIは追加していません。POST `/actions/s14_*` は役割別に検証。本人操作はセッションの本人IDを使用し、送信値の別人IDを信用しません。対象区分はサーバーで制限し、他人の申込は表示しません。

事業担当者は許可事業のセミナー情報・匿名集計・内部タスクだけ。氏名/参加者一覧・送信待ち/原稿・明示財務配賦・代表確認は代表専用です。権限外事業ID/根拠IDは拒否し、旧初回登録・カードHMAC・LINEの同意/停止/再同意/予約時停止モックを維持します。別LINE本体との接続/回帰は未実施です。

実データへの版14適用は今回していません。適用前には代表が承認して次を行います。

1. サーバー停止後、既存ops backupで新規の整合性あるスナップショットを取得。WALを落とす単純コピーをしない。
2. ops restoreで**別の新規検証DB**へ復元。新コードでOfficeを初期化すると版14をトランザクション適用。health/外部キー、既存件数、対象区分、同意/停止、旧画面を確認する。
3. 復元コピーは既存の隔離に加え、追加予定を停止、社員タスクを停止、成果物/原稿を再承認待ち、承認者解除。元の参加回答・財務履歴は保全し、自動再開しない。
4. 切替は代表の判断後だけ。原本・バックアップを上書き/削除せず、新しい出力パスを使う。
5. ロールバックは旧コードと移行前DBコピーを別パスで検証し、新DBを残して差分照合。**旧コードを新DBに向けない**：新しい厳密な対象区分を旧コードは理解しないためです。DROP/破壊的な逆移行や自動転記はしません。

コマンドは [運用マニュアル](runbook.md)。平文SQLite/バックアップの暗号化・法定保存・保持/削除・TLS/MFA・本番同意文面と最新脆弱性確認は未完了。本版のローカルモック同意を本番送信の同意取得済みと扱いません。

## 利用・検証方法

新規ローカル検証DBの場合のみinitします。既存DBは先にバックアップ/復元コピーを使ってください。

```sh
python3 -m violet_office.web init
python3 -m violet_office.web serve --open-browser
python3 -m violet_office.seminar_support_demo
python3 -m unittest discover -v
python3 -m tests.browser_phase14 --output-dir /tmp/violet-phase14-browser-new
```

PC自身で起動後、代表は `http://127.0.0.1:8765/seminar-office` →事業選択→手動登録。新規セミナーの初期モードは合成mock、実績確認用manualは代表が明示選択します。作成後のmode変更はしません。既存セミナーは先に既存「複数事業」で明示関連付け、拡張の採用操作をします。

本人確認は既存「セミナー管理」で代表が行い、参加者が初回登録し代表承認。ディーラー等のカードHMACは既存 `SEMINAR_CARD_HMAC_KEY` が必要で、実キーをGitや画面へ貼りません。新しい外部APIキーは不要です。

本人はログイン後「申込・参加希望」で回答、全体の再案内同意に加えて目的別同意・停止/関心を設定。代表は個別/一斉下書き→プレビュー・修正→個別承認→予定到来後のモック実行を確認。参加後は根拠を確認して実参加/欠席、明示面談希望/完了を記録します。これらの操作で実LINE配信や予約は起きません。

390pxはPCの開発者ツールで確認可能。iPhone実機は未検証で、ループバック限定サーバーを無断LAN公開しません。クラウドのlocalhostを手元PCから直接開ける意味ではありません。
