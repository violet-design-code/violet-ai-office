# 会計閲覧ポリシー 第1段階（独立・未適用）

この文書は第1段階時点の記録です。旧経路の接続、追加スキーマ、互換性と残る制限の現状は [旧会計経路の保護実装](legacy-accounting-enforcement.md) を参照してください。通常起動によるスキーマ自動導入・本番ポリシー適用は引き続き行いません。

既存の社員定義・担当・finance_read・activeを保持する追加サービスです。Office、Web、起動スクリプトから自動初期化・自動利用しません。実DBへの適用、外部送信、送金、記帳はありません。既存の修復試験プログラムとも独立しています。

## 構成

- `violet_office/accounting_access.py`: 明示初期化、ポリシー申請・代表承認/却下・失効、参照、専用参照IDによる引き継ぎ。
- `tests/test_accounting_access.py`: 一時合成DBのみ。通常起動へ接続しません。
- 本文書: 範囲、制限、Windows試験、後続承認事項。

`initialize_sandbox(office, principal)` は現在の代表アカウントを確認し、明示呼び出し時だけ `acct_policies / acct_sources / acct_handles / acct_events` を作ります。自動移行番号・Webルート・本番用CLIはありません。現段階では一時合成DB以外で呼び出さないでください。通常のOffice生成ではこれらのテーブルは作りません。

ポリシーには事業ID、社員ID、閲覧区分、許可項目、対象期間（開始日以上・終了日未満）、目的、申請者、承認者、タイムゾーン付き有効期限、状態を保存します。変更APIはなく、変更時は旧ポリシーを失効して新規申請します。既存のpermissions JSONは書き換えません。代表以外は承認・確認済みデータ登録を行えません。承認処理は合成テストでのみ実行しています。

役職一致は既存config/agents.jsonで確認済み。役職の上下関係から閲覧範囲を継承しません。次は候補上限であり、自動付与ではありません。全区分で個別の代表承認が必要です。

既存finance_readとは独立しています。新機能ではfinance_read/workの付与を要求せず、現在の事業別担当activeとbf_profiles.enabledを確認します。タスクの社員・事業はportfolio_tasksとtasksから特定し、クライアントの社員ID指定を信用しません。タスク状態・wf_tasks/s14_workの停止、現時点の代表承認者、期限、対象期間、項目を参照時に検査します。会計アクセスは既存の業務実行権限を追加しません。

読み取りと引き継ぎの認可・データ取得は既存のトランザクション機構で一体化します。取得結果は事業ID・期間・区分・出典種別を伴います。nullを0に変換せず、既存の売上基準と通貨分離に従います。全事業まとめ取得は実装せず、事業ごとに判定します。

## 意図的に狭めた範囲

- 明細・監査は `portfolio_ledger` のactual記録のみ。SCM請求書、銀行明細、証憑、氏名、連絡先、口座、自由記述evidence、添付・ログ・履歴の取得機能は提供しません。監査対象はこのデータ源・事業・期間・許可項目の範囲です。特定伝票のみの選別、証憑監査は今後別途設計が必要です。
- AI01とAI02は初期実装では同じ3項目が候補ですが、区分は別です。全事業集計・詳細な経営分析は自動付与しません。
- 広告費の分類を既存経費から推測しません。`approved_source` で代表が確認した数値事実だけを独立保存します。日付別の確認値を返し、勝手に合算・重複排除しません。
- 報酬条件も確認済み数値事実だけです。公式規約を確認したと自動認定せず、報酬条件全文・施策/制度ID・版・撤回・適用期間の完全管理は未実装です。本番での契約条件判断には使えません。
- systemは既存の事業別経費と処理秒数のみ。一般的な稼働監視API、任意ログ参照、秘密情報参照はありません。
- 小さい母数や期間差分から集計値が特定明細を推測させる可能性があります。統計的な秘匿処理・問い合わせ回数制限は未実装です。本番接続前に母数・粒度・期間の制約を追加検討してください。

## 引き継ぎ・成果物の境界

`issue` は金額や文章を保存しない専用参照IDを生成します。`receive` は送信元の現在のポリシーとタスク、受領側のポリシーとタスク、事業一致を毎回再確認して再取得します。許可区分・項目が一致しない場合は拒否します。明細を自動的に要約して下位権限へ流しません。AI27からAI02へ渡すときは、AI02の集計ポリシーで別途取得します。

専用テーブルには会計本文・添付・自由文成果物を保存しません。イベントにはポリシーID、固定アクション、実行者、日時のみ保存します。広告・条件データは許可された数値のみで、元文書の本文を受け付けません。

**既存の汎用artifact.read、文章、添付、ログ、履歴は今回一括改修していません。新サービスが返したデータをそれらへコピーした後のアクセス制御は、この独立機能だけでは保証できません。** 新機能の会計引き継ぎは専用参照IDのみで扱い、一般成果物へ保存する本番連携は未許可です。任意のSQLやファイル読み取りをAIへ渡す構成も対象外です。将来の本番接続前に、共通の内容区分と汎用成果物の受領者検査が必要です。
