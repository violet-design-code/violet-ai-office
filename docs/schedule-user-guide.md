# スケジュール管理：はじめての操作手順

確認日：2026年10月28日（日本時間）。対象ブランチ：`feature-voice-schedule`。

現在使えるのは、代表専用のローカル予定管理、日本語の候補解析、通知モック、カレンダーファイルの手動書き出しです。iPhoneへの自動実通知・Google同期・実音声の動作は確認できていません。経理自動化の追加には着手していません。

## 1. 最初に用意するもの

- Python 3.12以上が入ったPC。
- このブランチのプログラム一式。mainだけでは追加機能を利用できません。GitHubで `feature-voice-schedule` を選び、Code → Download ZIPで取得して展開するか、Gitでこのブランチを取得します。
- 初めて試す場合は、新しいフォルダーと練習用DBを使ってください。既存のプログラムフォルダーや業務DBに上書きしません。

Gitで新しいコピーを作る場合の例：

```sh
git clone --branch feature-voice-schedule https://github.com/violet-design-code/violet-ai-office.git violet-schedule-practice
cd violet-schedule-practice
```

以下のコマンドは、このフォルダーで実行します。Windowsでは展開したフォルダー内からターミナルを開いてください。Pythonの確認は `py -3 --version`、macOS/Linuxは `python3 --version` です。

## 2. 初回だけ：練習用アカウントを作る

Windows：

```sh
py -3 -m violet_office.web init --db var/schedule-practice.sqlite3
```

macOS/Linux：

```sh
python3 -m violet_office.web init --db var/schedule-practice.sqlite3
```

代表用と閲覧者用に、それぞれ異なる12文字以上のパスワードを設定します。入力中に文字が表示されないのは正常です。ユーザー名は `representative` と `viewer` になります。スケジュールを使うときは代表の `representative` でログインします。

**すでに使っているDBにはinitを行わないでください。** 作成済みと表示された場合も削除せず、既存のアカウントを使用します。パスワードをチャットに貼らないでください。

練習用DBには業務データをコピーしません。AI社員28人の設定は既存の設定ファイルから参照します。事業未登録なら、最初は「代表個人の予定」で試せます。

## 3. 起動する

Windows：

```sh
py -3 -m violet_office.web serve --db var/schedule-practice.sqlite3 --open-browser
```

macOS/Linux：

```sh
python3 -m violet_office.web serve --db var/schedule-practice.sqlite3 --open-browser
```

起動したターミナルは開いたままにします。ブラウザーが開かない場合は、**起動したPCのブラウザー**のアドレス欄へ次を入力します。

```text
http://127.0.0.1:8765/
```

代表アカウントでログインしてください。既存の業務DBを利用する場合は、先にバックアップを作り、`--db` に実際のDBパスを指定します。既存の起動方法も使用できますが、Office起動時に追加テーブルの移行が適用されます。まず練習用コピーで確認してください。

ポート使用中の場合は、別のVIOLET AI OFFICEが起動していないか確認します。別ポートを使う場合は `--port 8766` を追加し、URLも `http://127.0.0.1:8766/` にします。ネットワーク公開設定は変更しません。

## 4. スケジュール画面を開く

上部メニューの「スケジュール管理」をクリックします。直接開く場合：

```text
http://127.0.0.1:8765/schedule
```

閲覧者・事業担当・セミナー参加者には代表の予定を閲覧・変更する権限はありません。複数の代表アカウントがあっても、自分が登録した予定だけを扱います。

## 5. 予定を新しく登録する

1. 「予定の新規登録」へ進みます。
2. 「予定の内容」に `動作確認用の打ち合わせ` と入力します。
3. 「相手」「場所」は必要な場合だけ、まずは架空の内容で入力します。
4. 開始日時と終了日時を入力します。すべて日本時間です。終了日時を推測して自動補完することはありません。
5. 事業未登録の練習なら「代表個人の予定」を選びます。事業を選ぶ場合は既存の事業IDに紐付き、顧客データを自動コピーしません。
6. 「日時・相手・場所・内容を確認しました」にチェックします。
7. 「確認した予定を保存」を押します。
8. 画面の「保存しました」という返答と、予定一覧への反映を確認します。保存に失敗した場合は成功と返答しません。

登録例は、操作した日の翌日の14:00〜15:00など、未来の日時で試してください。他の自分の予定と重なると登録を拒否します。別事業の自分の予定との重複も検知します。既存の顧客予約・セミナー・外部カレンダーは自動取込していないため、そこまで含む空き時間保証ではありません。

## 6. 登録した予定を確認する

1. 「予定の確認」の「表示開始日」を登録した日にします。
2. 必要に応じて事業を選びます。
3. 「予定を表示」を押します。選択日から7日間を表示します。
4. 画面を再表示しても予定が残ることを確認してください。

「日本語の指示」に、`今日の予定を教えて`、`明日の予定は？`、`来週の予定を教えて`、`次の予定は何時？` と入力して「指示を確認・検索する」を押すこともできます。検索結果は登録済みの本人の予定から返します。「次の予定」は開始前の予定を対象とします。

空き時間は「空き時間」欄で日・検索開始・終了を選び、ボタンを押します。09:00〜18:00は変更できる検索範囲で、事業の営業時間を確定した値ではありません。`金曜日の空いている時間は？` の曜日は、今日を含めて次に来る該当曜日です。来週は月曜〜翌月曜直前です。

## 7. 予定を変更する

1. 予定一覧の「変更・キャンセル」を押します。
2. 内容・日時・相手・場所・事業を変更します。
3. 確認チェックを入れ、「確認した予定を保存」を押します。
4. 保存の返答と一覧を確認します。

他のタブから先に編集されていた場合は古い内容で上書きしません。入力・状態のエラーが表示されたら、一覧を開き直して最新の予定を確認してください。

## 8. 予定を削除扱いにする（キャンセル）

1. 一覧で「変更・キャンセル」を押します。
2. 「この予定をキャンセルします（物理削除せず履歴保持）」にチェックします。
3. 「予定をキャンセル」を押します。
4. キャンセル完了の返答を確認します。

予定一覧と通知対象から外れます。**現在の削除操作は論理キャンセルです。DBからの完全消去は実装していません。** 操作履歴を保持するため、削除したと説明して物理消去済みと扱うことはありません。既存の事業・顧客データは削除しません。

## 9. 前日21時・開始60分前の通知設定

現在の通知設定は**モック検証用**です。設定してもiPhone・LINE・メールへ送信しません。

1. 「通知の設定・状態」を開きます。
2. 「30秒周期のローカル通知モックを有効にする」にチェックします。
3. 「代表本人の予定を通知準備に使うことに同意」にチェックします。
4. 「設定を確認しました」にチェックします。
5. 「通知設定を保存」を押します。
6. 「現在時刻で通知をモック検証」を押すか、起動中のサーバーで約30秒待ちます。
7. 通知予定欄の日時・状態を確認します。

- 前日21:00（Asia/Tokyo）：翌日の予定をまとめた1件を準備。予定のない日は作りません。日を跨ぐ継続予定も対象です。
- 開始60分前：予定ごとに1件。標準は30分前ではありません。
- 「通知準備済み」は未実行。「モック成功・実配信なし」は模擬処理が終わった状態で、スマートフォン配信成功ではありません。
- 通知後に文章・場所だけを修正しても同じ開始時刻の通知を再送しません。開始時刻を変更した場合は新しい時刻の通知を準備します。
- 失敗モックは30秒間隔・最大3回。サーバー停止などで5分以上遅れた通知は「遅延のため未実行」にし、古い案内を送らない設計です。
- 通知停止は有効チェックを外して保存します。同意も撤回できます。

短時間で試す場合は、開始を現在から約61分後にして登録すると約1分後に60分前の処理を確認できます。前日21時の判定は固定時計を使う自動テストで検証済みで、動作確認のためにPCの時計を変更する必要はありません。

PCがスリープ中、電源OFF、アプリ停止中は処理できません。サーバー常駐化・OSの通知デーモン・実Pushは未設定です。

## 10. 音声入力・音声回答

1. 「音声・日本語指示」の対応状況を確認します。
2. 「端末内で音声入力」が有効な場合だけ開始し、ブラウザーのマイク許可を確認します。
3. 認識文字を確認して、「指示を確認・検索する」を押します。
4. 登録候補が表示されたら、年・開始・終了・相手・場所・内容を修正・確認します。
5. 最後に確認チェックと保存ボタンで登録します。音声認識だけで自動保存しません。
6. 対応する日本語の端末内音声がある場合、「回答を端末内で読み上げ」で回答を聞けます。

例：`11月5日の14時から石川さんと佐久市で打ち合わせするから予定入れて`。年と終了日時が不足しているため確認が必要です。自然言語の解釈はルールベースで、任意の言い回しを理解するLLMは接続していません。変更・キャンセルの指示では、一覧から対象を選んで確認する手順へ案内します。

ボタンが無効な場合、端末内の日本語認識または日本語音声がありません。外部の音声認識サービスや音声パックの自動インストールへは切り替えません。文字入力を利用してください。OS側の音声入力を使う場合は、利用者自身がOS側の外部処理・プライバシー設定を確認してください。

今回確認したのはブラウザー音声APIの**モックによる入出力処理**です。実マイク、実際の音声再生、Windows/macOS/iPhone実機の音声動作は未確認です。

## 11. iPhone通知の現在地

- 現行サーバーはPC内の127.0.0.1専用です。iPhoneで同じURLを入力してもPCの画面には接続できません。
- iPhoneから予定を直接管理するためのHTTPS接続環境は未設定です。
- Web Pushの購読・VAPID鍵・サービスワーカー、LINE本人宛通知、Google OAuthと双方向同期は未実装・未接続です。
- 「iPhoneカレンダー向け手動書き出し」は、代表が内容の持ち出しに同意したうえでICSをダウンロードする機能です。カレンダーへの取込・通知許可・ロック画面設定は端末側での手動操作になります。iPhone実機での取込と通知は未検証です。
- ICSは自動同期ではありません。アプリ側の変更・キャンセルは端末の旧予定へ自動反映されません。再取込時の重複や古い通知は端末側で整理する必要があります。日を跨ぐ予定のICS一覧通知は開始日単位です。

実通知へ進むには、代表による接続方式の確認、保護されたHTTPS環境、端末側の通知許可、必要な外部サービス認証・安全な秘密情報保管、実機テストが必要です。承認前に外部認証・本番通知・公開を開始しません。認証情報をソースやチャットに貼らないでください。

## 12. 終了・次回起動・バックアップ

- 終了：起動したターミナルで `Ctrl+C`。
- 次回：同じフォルダー・同じ `--db` で `serve` を実行します。毎回initする必要はありません。
- バックアップ例（毎回新しいファイル名にする）：

```sh
python3 -m violet_office.ops backup --db var/schedule-practice.sqlite3 --output var/backups/schedule-practice-NEW.sqlite3
```

Windowsでは `python3` を `py -3` に置き換えてください。バックアップは平文で個人予定を含むため、アクセスを制限して保管します。復元は既存DBを上書きせず新しいパスへ行う既存手順を使用します。復元後は通知有効・同意を解除し、通知を保留するので、内容を確認してから再設定します。
