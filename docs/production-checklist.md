# 本番移行チェックリスト（未承認・移行禁止）

現版の判定は**本番移行不可**。チェックが揃っても自動デプロイや送信を行わず、最終的に代表の明示承認を得る。設定フラグで本番アダプターを有効化する経路もない。

## 必須の8条件

- [ ] 必須ローカル/モック試験が最新ソースで合格し、対象サービスのステージング試験も合格
- [ ] 重大な未解決セキュリティ問題がないと、人による監査で判断できる
- [ ] 実際に採用するLINE/予約/SNS/LLM/CRMの正規API、権限、期限、料金、接続状態を確認
- [ ] 送信直前の宛先・同意・停止・予約・原稿版・承認・重複防止・結果照会を実APIの安全な環境で検証
- [ ] 承認と実行を分離し、承認者・時刻・対象版・判断を記録
- [ ] 既存LINE本体の停止・再同意・7日間配信・予約時停止・重複/再試行の回帰試験が合格
- [ ] 暗号化バックアップ、復元、整合性、実行隔離、業務照合、担当者の復旧演習が確認済み
- [ ] 代表が対象バージョン・環境・機能・上限・日時・停止手順を指定し、本番移行を明示承認

## 環境とデータ

- [ ] テストと本番のアカウント/DB/鍵/宛先/監査先を分離。合成の同意・承認・予約・費用を本番へ移行しない
- [ ] TLS、Secure Cookie、MFA、アカウント運用、最小権限、CSRF/XSS、入口のアクセス制限と監査を設計
- [ ] Python/SQLite/OpenSSL/OSと採用依存の最新版アドバイザリを照合、パッチ適用と再検証
- [ ] 暗号化したID対応保管庫、鍵管理/ローテーション、保持期限・削除・バックアップ保持を確定
- [ ] APIタイムアウト、確実に未受付の場合だけの再試行、結果不明照合、費用予約/精算・請求照合・利用数上限を実装
- [ ] 監査ログ保全、障害対応担当、復旧目標、連絡経路を代表が決定。未接続通知サービスは未接続と表示
